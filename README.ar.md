# 🛒 متجر إلكتروني — Frontend

[English](README.md) | **العربية**

واجهة المتجر الإلكتروني، مبنية باستخدام **React** و **Vite**، وتتواصل مع [الـ Backend API](../backend/README.ar.md).

أهم المميزات:

- صفحة عرض المنتجات وصفحة تفاصيل المنتج.
- سلة مشتريات بدون تسجيل دخول (باستخدام `guestId` محفوظ في المتصفح).
- شراء مباشر وشراء من السلة، مع تأكيد الطلب عبر واتساب.
- صفحة "طلباتي": الطلبات المحفوظة على هذا الجهاز، دائماً ببيانات جديدة (برمز التأكيد + رقم الهاتف، بدون تسجيل دخول).
- لوحة تحكم للأدمن: المنتجات، الطلبات، حسابات الأدمن، والإحصائيات.
- صفحات محمية حسب الصلاحية (`admin`، `moderator`، `super_admin`).
- لغتان: **العربية** (الافتراضية، من اليمين لليسار) و **الإنجليزية** (من اليسار لليمين)، مع زر للتبديل في كل الصفحات.

## ⚙️ الإعداد والتشغيل

جميع الأوامر تُنفَّذ من داخل مجلد `frontend/`.

### 1. تثبيت الحزم

```bash
cd frontend
npm install
```

### 2. إعداد متغيرات البيئة

انسخ ملف المثال (للتطوير المحلي) داخل `frontend/`:

```bash
cp .env.example .env.development
```

ملف `.env.example` موجود في git ولا يحتوي أسراراً. قيم `VITE_` تظهر في المتصفح، لذلك لا تضع فيها أي سر. للإنتاج، ضع نفس المتغير في Vercel ← **Environment Variables**. الملف:

```env
VITE_API_URL=http://localhost:5000
```

`VITE_API_URL` هو عنوان الـ Backend **بدون** `/api` في النهاية. في الإنتاج (Vercel) أضف نفس المتغير من إعدادات المشروع.

### 3. التشغيل

```bash
npm run dev
```

يعمل التطبيق على `http://localhost:5173` (الافتراضي في Vite).

### أوامر أخرى

| الأمر             | الوظيفة                               |
| ----------------- | ------------------------------------- |
| `npm run build`   | بناء نسخة الإنتاج (`dist/`)           |
| `npm run preview` | معاينة نسخة الإنتاج                   |
| `npm run lint`    | فحص الكود باستخدام ESLint             |

> يجب تشغيل الـ Backend أيضاً. راجع [ملف الـ Backend](../backend/README.ar.md).
>
> ⚠️ الـ Backend يسمح بـ CORS origin واحد فقط وهو `FRONTEND_URL`. للتطوير المحلي ضع `FRONTEND_URL=http://localhost:5173` في `backend/.env`، وإلا سيمنع المتصفح الطلبات.
>
> ⚠️ الشراء لا يعمل حتى يتم حفظ رقم واتساب المتجر مرة واحدة: من صفحة الأدمن **⚙️ إعدادات المتجر** (`super_admin`)، أو `node scripts/storeSettingsSeed.js +970599123456` (من `backend/`). بدونه يرجع الـ API الكود `503`.

### التجربة على الهاتف (نفس شبكة الـ Wi-Fi)

1. اعرف IP الكمبيوتر (`ipconfig`)، مثلاً `192.168.1.16`.
2. ضع `VITE_API_URL=http://192.168.1.16:5000` في `frontend/.env.development` و`FRONTEND_URL=http://192.168.1.16:5173` في `backend/.env`.
3. **أعد تشغيل السيرفرين** (السيرفر الشغّال لا يقرأ `.env` من جديد). شغّل الـ Frontend بـ `npm run dev -- --host`.
4. افتح `http://192.168.1.16:5173` على الهاتف. استخدم الـ IP على الكمبيوتر أيضاً وليس `localhost`، وإلا سيمنعه CORS.

> على `http` (وليس `https`) الهاتف يمنع النسخ، لذلك زر **نسخ** رمز التأكيد يُظهر خطأ. على Vercel يعمل.

## 🌐 اللغات (i18n)

الموقع يدعم **العربية** و **الإنجليزية** باستخدام [react-i18next](https://react.i18next.com/).

| الموضوع | التفاصيل |
| ------- | -------- |
| اللغة الافتراضية | العربية (`ar`) |
| التبديل | زر 🌐 أسفل يمين كل صفحة (`components/languageSwitcher/`) |
| حفظ الاختيار | `localStorage` (المفتاح: `lang`) |
| الاتجاه | `<html dir>` يتغير تلقائياً: `rtl` للعربية، `ltr` للإنجليزية |
| التواريخ | بلغة الموقع، مع أرقام إنجليزية (0–9) |
| ملفات النصوص | `src/i18n/ar.json` و `src/i18n/en.json` (نفس المفاتيح في الملفين) |

**لإضافة نص جديد:** أضف نفس المفتاح في **الملفين**، ثم استخدمه في المكوّن:

```jsx
import { useTranslation } from "react-i18next";

const { t } = useTranslation();
<p>{t("cart.emptyText")}</p>
<p>{t("stock.few", { count: 3 })}</p>   // مع قيمة: "متبقي {{count}} فقط"
```

خارج مكوّنات React (مثل Zustand stores) استخدم `i18n.t("key")` من `src/i18n`.

> الرسائل القادمة من الـ Backend (مثل أخطاء الـ API) بالعربية فقط. أسماء المنتجات تأتي من قاعدة البيانات ولا تُترجم.

## 💰 الأسعار والعملة

المتجر يستخدم **الشيكل (₪)**. كل الأسعار في الموقع تمر عبر دالة واحدة: `src/utils/formatPrice.js`:

```js
import { formatPrice } from "../../utils/formatPrice";

formatPrice(1099); // "1,099.00 ₪"
formatPrice(9.5);  // "9.50 ₪"
```

- فاصلة للآلاف، ورقمان بعد الفاصلة دائماً، و`₪` بعد الرقم. أرقام إنجليزية (0–9) في اللغتين.
- القيمة الناقصة أو الخاطئة تظهر `0.00 ₪` (بدون أي خطأ).
- لتغيير العملة أو الشكل، عدّل ملف `formatPrice.js` **فقط**. لا تكتب `₪` مباشرة في المكوّنات أو في ملفات الترجمة.

## 🔐 كيف يعمل تسجيل دخول الأدمن

1. الأدمن يرسل الإيميل وكلمة المرور إلى `POST /api/auth/login`.
2. الـ Backend يرجع JWT Token.
3. يتم حفظ التوكن في `localStorage` (المفتاح: `token`)، وقراءة الصلاحية منه باستخدام `jwt-decode`.
4. `ProtectedRoute` يتحقق من الصلاحية، وإذا كانت غير مسموحة يرجع المستخدم إلى `/`.
5. `utils/axiosAdmin.js` يضيف `Authorization: Bearer <token>` لكل طلبات الأدمن.
6. عند فتح التطبيق، يتم حذف التوكن المنتهي تلقائياً.

> التحقق من الصلاحية في الـ Frontend هو للواجهة فقط. الحماية الحقيقية موجودة في الـ Backend.

## 🛒 كيف تعمل سلة الضيف

1. عند أول زيارة، ينشئ التطبيق `guestId` (UUID v4) ويحفظه في `localStorage`.
2. جميع طلبات السلة ترسل هذا الـ `guestId` في الرابط (`/api/carts/:guestId/...`).
3. لا حاجة لتسجيل الدخول.

## 💬 كيف يعمل تأكيد الطلب عبر واتساب

1. بعد نجاح الشراء (مباشر أو من السلة)، نافذة إتمام الطلب تتحول إلى شاشة التأكيد (`components/whatsAppConfirm/`).
2. تعرض رمز التأكيد (6 خانات)، وزر **نسخ**، والوقت المسموح (24 ساعة، مع التاريخ والوقت).
3. زر **تأكيد عبر واتساب** يفتح `whatsappUrl` القادم من الـ Backend: محادثة مع المتجر والرمز مكتوب جاهز.
4. ملاحظة تقول إن المتجر سيؤكد الطلب، وإن الحالة يمكن متابعتها لاحقاً. الأزرار: **اذهب إلى طلباتي** و**تم**.
5. الضغط خارج هذه الشاشة لا يغلقها، حتى لا يضيع الرمز بالغلط.

> الشاشة **لا** تسأل السيرفر عن حالة التأكيد. هذا المسار (`GET /api/orders/:id/confirmation`) مقفل حتى يتم بناء بوت واتساب.

صفحة **طلباتي** تعرض شارة على كل طلب: بانتظار التأكيد (مع الرمز)، مؤكد، أو منتهي. الطلب الذي لا يُؤكَّد خلال **24 ساعة** يلغيه السيرفر (الحالة **ملغي** + شارة **منتهي**)، ومخزونه يرجع.

**صفحة طلبات الأدمن** (`/admin/orders-management`): كل طلب يعرض حالة التأكيد والرمز. وما دام بانتظار التأكيد، زر **تأكيد الطلب** يفتح نافذة ("أكّد فقط إذا وصلك الرمز X من الرقم Y")، ثم يستدعي `POST /api/orders/confirm`.

> التأكيد التلقائي (بوت واتساب) لم يتم بناؤه بعد. حالياً المشرف يؤكد يدوياً.

## 🔎 تتبّع الطلب بالرمز (الصفحة الرئيسية)

زر **🎁 طلباتي** في الصفحة الرئيسية يفتح `components/trackOrder/TrackOrder.jsx`:

> 📋 إذا كان على هذا الجهاز طلبات محفوظة، يظهر في الأعلى زر أخضر **📋 مشاهدة الطلبات المحفوظة على هذا الجهاز** مع عدد الطلبات المحفوظة. يفتح صفحة "طلباتي". وتحته: "أو تتبّع طلباً آخر برمز التأكيد:". إذا لا توجد طلبات محفوظة، يظهر الفورم فقط.
1. الزبون يدخل **رمز التأكيد** (من شاشة واتساب بعد الشراء) و**رقم هاتفه** مع رمز الدولة.
   - الرمز يتحول لحروف كبيرة وتُحذف المسافات (`k7p 2xm` ← `K7P2XM`). يجب أن يكون 6 خانات بدون `0 O 1 I L`، وإلا يظهر تنبيه أصفر ويبقى الزر معطّلاً.
2. الدالة `trackOrder()` في `useOrderStore.js` ترسل الاثنين إلى `POST /api/orders/track`.
3. إذا وُجد الطلب، نفس النافذة تعرضه: الرمز، حالة الطلب، شارة تأكيد واتساب، التاريخ، المنتجات، والإجمالي. ويُحفظ الطلب أيضاً **على هذا الجهاز** (فيظهر في "طلباتي"). الأزرار: **✖ إلغاء الطلب** (فقط للطلب **Pending**، انظر [إلغاء الطلب](#-إلغاء-الطلب))، **عرض كل طلباتي** و**تتبّع طلب آخر**.
4. إذا لم يوجد، تظهر رسالة السيرفر في toast.

> رقم الهاتف مطلوب أيضاً: من يعرف رقم الهاتف فقط لا يستطيع رؤية الطلبات بهذه الطريقة.

## 📦 كيف تعمل صفحة "طلباتي" (محفوظة على هذا الجهاز)

**لا يوجد تسجيل دخول ولا توكن.** المتصفح يحفظ قائمة صغيرة بطلبات الزبون في `localStorage` (المفتاح: `savedOrders`، الملف `utils/savedOrders.js`):

```json
[{ "code": "K7P2XM", "phoneNumber": "+970599123456", "savedAt": "2026-11-26T12:00:00.000Z" }]
```

1. **يُحفظ تلقائياً** بعد كل عملية شراء (`CompleteOrder.jsx`)، وعندما يُعثر على طلب في TrackOrder (مفيد على جهاز جديد: الرمز موجود في محادثة واتساب الزبون).
2. يُحفظ `code + phoneNumber` فقط، **وليس** بيانات الطلب. الأحدث أولاً، ولا يُحفظ نفس الرمز مرتين، والقائمة **50** طلباً كحد أقصى.
3. كل مرة تُفتح "طلباتي" (أو refresh)، الدالة `fetchSavedOrders()` تطلب **بيانات جديدة** من `POST /api/orders/track-many`. أكثر من 20 طلباً محفوظاً ← عدة طلبات، كل واحد 20.
4. كل طلب يعرض التاريخ، الحالة، شارة تأكيد واتساب، المنتجات والسعر. فلتر الحالة والإجمالي يعملان على هذه الطلبات.
5. الطلب الذي لا يجده السيرفر يظهر **"الطلب غير موجود"** مع رمزه (مثلاً إذا حُذف).
6. 🗑️ على كل طلب و**حذف الكل** يحذفان الطلبات **من هذا الجهاز فقط** (الطلب **لا** يُلغى). كلاهما يسأل أولاً بنافذة التأكيد.
7. لا توجد طلبات محفوظة ← رسالة تشرح كيف تضيف طلباً (الشراء، أو 🎁 طلباتي + الرمز).
8. الطلبات التي تمت **قبل** هذه الميزة غير محفوظة على الجهاز. أدخل الرمز + الرقم مرة واحدة في 🎁 طلباتي لإضافتها.

> الـ `guestToken` القديم في `localStorage` يُحذف مرة واحدة عند فتح التطبيق (جلسات الضيف حُذفت من الـ Backend).

### ✖ إلغاء الطلب

- كل طلب **Pending** فيه زر أحمر **إلغاء الطلب**، في "طلباتي" **وفي** نافذة TrackOrder. الطلبات المقبولة، والتي تم توصيلها، والملغية لا يظهر فيها.
- الاثنان يستخدمان نفس الدالة `cancelOrder()`. ترجع `{ order }` عند النجاح، `{ failed: true }` عند الخطأ، أو `null` إذا اختار الزبون "لا، أبقِ الطلب".
- في TrackOrder، النافذة تعرض **ملغي** مباشرة. عند الخطأ تسأل `/track` من جديد، لتعرض الحالة الجديدة.
- الضغط يفتح نافذة التأكيد ("إلغاء الطلب" / "لا، أبقِ الطلب").
- الدالة `cancelOrder()` في `useOrderStore.js` ترسل `code + phoneNumber` المحفوظين إلى `POST /api/orders/cancel`. السيرفر يرجع المخزون.
- عند النجاح البطاقة تعرض **ملغي** مباشرة، والطلب **يبقى** في القائمة.
- إذا قبل المتجر الطلب قبل لحظة (`409`)، تظهر رسالة السيرفر، وتُجلب القائمة من جديد بالحالة الجديدة.
- الطلبات الملغية **لا** تدخل في الإجمالي.

## ⚙️ صفحة إعدادات المتجر (`/admin/store-settings`)

`pages/storeSettings/StoreSettings.jsx`، لـ **`super_admin` فقط**: المسار محمي، ورابط القائمة **⚙️ إعدادات المتجر** يظهر فقط لـ `super_admin`، والـ API يرفض باقي الصلاحيات.

1. تعرض رقم واتساب المتجر الحالي، ومتى ومن غيّره. بدون رقم، يظهر تنبيه أصفر أن كل عمليات الشراء متوقفة.
2. الفورم فيه كود الدولة والرقم. الرقم يُنظَّف مثل السيرفر (المسافات، `-`، وصفر واحد في البداية)، ويجب أن يكون 9 أرقام، وإلا يظهر تنبيه ويبقى زر **حفظ الرقم** معطّلاً.
3. قبل الحفظ، تعرض كيف سيُحفظ الرقم (`+970599123456`). لا يمكن حفظ نفس الرقم الحالي مرة أخرى.
4. زر **حفظ الرقم** يسأل أولاً بنافذة التأكيد، ثم `saveStoreWhatsApp()` ترسل `PUT /api/store-settings`.

## 🔌 الـ API المستخدمة

| القسم            | الـ Endpoints                                                                                 |
| ---------------- | --------------------------------------------------------------------------------------------- |
| تسجيل الدخول     | `POST /api/auth/login`                                                                        |
| الأدمنز          | `GET /api/admins`، `POST /api/admins`، `PATCH /api/admins/:id/disable`، `PATCH /api/admins/:id/enable` |
| الإحصائيات       | `GET /api/dashboard/analytics`                                                                |
| إعدادات المتجر   | `GET /api/store-settings`، `PUT /api/store-settings`                                          |
| الطلبات (الأدمن) | `GET /api/orders`، `PATCH /api/orders/:orderId`، `POST /api/orders/confirm`                   |
| تتبّع الطلب      | `POST /api/orders/track`، `POST /api/orders/track-many`، `POST /api/orders/cancel`            |
| المنتجات         | `GET /api/items`، `POST /api/items`، `PUT /api/items/:id`، `DELETE /api/items/:id`            |
| السلة            | `/api/carts/:guestId/...` (راجع ملف الـ Backend)                                              |
| الشراء           | `POST /api/orders`، `POST /api/carts/:guestId/checkout`                                       |
| حالة السيرفر     | `GET /health`                                                                                 |

التفاصيل الكاملة موجودة في [ملف الـ Backend](../backend/README.ar.md).

---

## 🌐 الاستضافة

الـ Frontend مستضاف على **Vercel**. ملف `vercel.json` يوجّه جميع المسارات إلى `index.html` حتى يعمل React Router عند تحديث الصفحة.
